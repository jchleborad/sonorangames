Sonoran Games is a private NFL Pick’em platform designed for approximately 20–25 players.

It should provide:

player registration and participation
weekly NFL game selections
automated NFL schedules, scores, and winners
automated pick grading
weekly winners
season standings and rankings
historical results
an attractive, responsive, interactive website
little or no weekly manual data entry

The project should remain essentially free to operate, apart from annual domain registration.

Ultimate goal

Build a polished, enjoyable NFL Pick’em application that feels like a real sports platform while continuing to use:

GitHub Pages for free website hosting
Google Sheets for data storage and administration
Google Apps Script for backend logic and JSON APIs
the native Sonoran Games website for weekly picks
ESPN’s scoreboard data as the primary NFL schedule and score source

The system must be reusable for the 2026 season and future seasons without rebuilding the underlying architecture each year.

4. Established Technical Decisions
Entire-season storage

Schedule and ScoresLive will retain all 18 regular-season weeks.

They will not be overwritten when the current week changes.

The engine uses an upsert model:

If a game ID already exists, update the existing row.
If it does not exist, append a new row.

This allows:

changed kickoff dates or times
postponed games
score updates
corrections
season history
past-week pages
weekly winner history
recalculation
Stable identifiers

All game-related tables must use ESPN’s stable:

game_id

Do not match data only through strings such as:

Chiefs vs Chargers

Player records use a stable:

player_id

The player ID should distinguish duplicate first names.

Current example:

JohnC

Lowercase IDs such as johnc were suggested for easier comparisons, but the existing capitalization is not technically invalid. Whichever convention is chosen should be consistent.

Multi-season support

Every major data table should include:

season
week

No core function should be hardcoded permanently to 2026.

Reusable functions should accept or read:

season
week
seasonType

Examples:

syncWeekFromEspn_(season, week, seasonType)
gradeWeek(season, week)
updateSeasonStandings(season)
NFL data source

Primary source:

ESPN scoreboard data

Test endpoint pattern:

https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard?dates=2025&seasontype=2&week=1

ESPN season types:

1 = preseason
2 = regular season
3 = postseason

NFL.com page scraping was rejected as the primary source because it is not structured as a dependable HTML table and is more likely to break.

Schedule changes

Schedule synchronization must update existing games by game_id.

If the NFL changes a Week 8 game:

kickoff information updates
the game retains the same database relationship
player picks remain tied to the same game ID
unusual cases can be handled through ManualOverrides

Pick-lock policy still needs to be formally established for games whose kickoff time changes after submissions begin.

Foundation helpers
function getSheet_(sheetName) {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const sheet = ss.getSheetByName(sheetName);

  if (!sheet) {
    throw new Error(`Missing sheet: ${sheetName}`);
  }

  return sheet;
}

function getHeaders_(sheetName) {
  const sheet = getSheet_(sheetName);
  return sheet
    .getRange(1, 1, 1, sheet.getLastColumn())
    .getValues()[0];
}

function getRowsAsObjects_(sheetName) {
  const sheet = getSheet_(sheetName);
  const values = sheet.getDataRange().getValues();

  if (values.length < 2) return [];

  const headers = values[0];

  return values
    .slice(1)
    .filter(row => row.some(cell => cell !== ''))
    .map((row, rowIndex) => {
      const obj = { _rowNumber: rowIndex + 2 };

      headers.forEach((header, index) => {
        obj[header] = row[index];
      });

      return obj;
    });
}

function clearDataRows_(sheetName) {
  const sheet = getSheet_(sheetName);
  const lastRow = sheet.getLastRow();
  const lastCol = sheet.getLastColumn();

  if (lastRow > 1) {
    sheet
      .getRange(2, 1, lastRow - 1, lastCol)
      .clearContent();
  }
}

function writeObjects_(sheetName, objects) {
  const sheet = getSheet_(sheetName);
  const headers = getHeaders_(sheetName);

  clearDataRows_(sheetName);

  if (!objects || objects.length === 0) return;

  const rows = objects.map(obj =>
    headers.map(header => obj[header] ?? '')
  );

  sheet
    .getRange(2, 1, rows.length, headers.length)
    .setValues(rows);
}

writeObjects_() clears all existing data and should therefore not be used for production schedule or score synchronization.

function loadPlayers_() {

      display_name: player.display_name,
      email: player.email,
      active: isActive,
      admin:

        String(player.admin).toUpperCase() === 'TRUE',
      tiebreaker_enabled:
        player.tiebreaker_enabled === true ||
        String(player.tiebreaker_enabled).toUpperCase() === 'TRUE'
    };
  });

  return lookup;
}

7. ESPN Import Code
Fetch ESPN scoreboard
function fetchEspnScoreboard_(season, week, seasonType) {
  const url =
    `https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard` +
    `?dates=${season}&seasontype=${seasonType}&week=${week}`;

  const response = UrlFetchApp.fetch(url, {
    muteHttpExceptions: true
  });

  const statusCode = response.getResponseCode();

  if (statusCode !== 200) {
    throw new Error(
      `ESPN request failed. Status: ${statusCode}`
    );
  }

  return JSON.parse(response.getContentText());
}
Parse ESPN games
function parseEspnGames_(data, season, week) {
  const events = data.events || [];

  return events.map((event, index) => {
    const competition = event.competitions[0];
    const competitors = competition.competitors;

    const home = competitors.find(
      competitor => competitor.homeAway === 'home'
    );

    const away = competitors.find(
      competitor => competitor.homeAway === 'away'
    );

    const awayScore =
      away.score === '' ? '' : Number(away.score);

    const homeScore =
      home.score === '' ? '' : Number(home.score);

    const statusType = competition.status.type;
    const isFinal = statusType.completed === true;

    let winner = '';

    if (isFinal) {
      if (awayScore > homeScore) {
        winner = away.team.abbreviation;
      }

      if (homeScore > awayScore) {
        winner = home.team.abbreviation;
      }

      if (awayScore === homeScore) {
        winner = 'TIE';
      }
    }

    return {
      season,
      week,
      game_id: event.id,
      kickoff_utc: event.date,
      kickoff_local: new Date(event.date),
      away_team: away.team.displayName,
      home_team: home.team.displayName,
      away_abbr: away.team.abbreviation,
      home_abbr: home.team.abbreviation,
      network: '',
      status: statusType.description,
      winning_team: winner,
      result_final: isFinal,
      week_sort: index + 1,

      scoreRow: {
        season,
        week,
        game_id: event.id,
        status: statusType.description,
        quarter: competition.status.period || '',
        clock: competition.status.displayClock || '',
        away_team: away.team.displayName,
        home_team: home.team.displayName,
        away_score: awayScore,
        home_score: homeScore,
        winner,
        is_final: isFinal,
        last_updated: new Date()
      }
    };
  });
}
8. Upsert Architecture
Current upsert helper
function upsertObjectsByKey_(sheetName, objects, keyField) {
  const sheet = getSheet_(sheetName);
  const headers = getHeaders_(sheetName);

  if (!objects || objects.length === 0) return;

  const existingRows = getRowsAsObjects_(sheetName);
  const rowByKey = {};

  existingRows.forEach(row => {
    if (row[keyField]) {
      rowByKey[String(row[keyField])] = row._rowNumber;
    }
  });

  objects.forEach(obj => {
    const key = String(obj[keyField]);

    if (!key) return;

    const rowValues = headers.map(
      header => obj[header] ?? ''
    );

    if (rowByKey[key]) {
      sheet
        .getRange(
          rowByKey[key],
          1,
          1,
          headers.length
        )
        .setValues([rowValues]);
    } else {
      sheet.appendRow(rowValues);
    }
  });
}

Potential future optimization:

The current implementation writes one row at a time. This is fine for the current scale but may later be changed to batch updates for efficiency.

Reusable weekly sync
function syncWeekFromEspn_(season, week, seasonType) {
  const data = fetchEspnScoreboard_(
    season,
    week,
    seasonType
  );

  const games = parseEspnGames_(
    data,
    season,
    week
  );

  const scheduleRows = games.map(game => ({
    season: game.season,
    week: game.week,
    game_id: game.game_id,
    kickoff_utc: game.kickoff_utc,
    kickoff_local: game.kickoff_local,
    away_team: game.away_team,
    home_team: game.home_team,
    away_abbr: game.away_abbr,
    home_abbr: game.home_abbr,
    network: game.network,
    status: game.status,
    winning_team: game.winning_team,
    result_final: game.result_final,
    week_sort: game.week_sort
  }));

  const scoreRows = games.map(
    game => game.scoreRow
  );

  upsertObjectsByKey_(
    SHEETS.SCHEDULE,
    scheduleRows,
    'game_id'
  );

  upsertObjectsByKey_(
    SHEETS.SCORES_LIVE,
    scoreRows,
    'game_id'
  );

  appendAuditLog_(
    'SYNC_WEEK_ESPN',
    'espn',
    `${season}-W${week}`,
    `Upserted ${games.length} game(s) for season ${season}, week ${week}`
  );

  return games.length;
}

Use clean JSON APIs so Apps Script/Sheets can eventually be replaced without rebuilding the entire frontend.

D-016 — Weekly picks interface

Players enter, review, submit, and update weekly selections directly on SonoranGames.com. Google Forms will not be used for weekly picks.

D-017 — Raw and normalized pick records

PicksRaw is an append-only receipt log containing one record per submitted card or update. PicksNormalized contains one current game-level record per player and game and is used for locking, grading, results, and display.

D-018 — Game locking

Each game locks independently at its official kickoff. A Thursday selection locks while later games remain editable. Backend time is authoritative.

D-019 — Working ownership

John owns pool rules, player experience, commissioner policy, financial/fairness decisions, and final acceptance. Codex owns technical architecture, implementation, testing, and documentation and should request John's input only when a decision materially affects rules, fairness, cost, privacy, security, destructive changes, or player experience.
